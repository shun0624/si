# 通帳から仕訳を作る

過去の総勘定元帳（その銀行口座の部分）と、預金通帳のコピーを受け取り、仕訳をExcelで出力する。
**分からないものは推測で埋めず、「不明」のまま出す。** これがこのスキルで一番大事な約束。

## 全体の流れ

1. 受け取った資料を確認する
2. 元帳を `ledger.csv`（標準形式）にする
3. 通帳を読み取り、`passbook.csv`（標準形式）にする
4. `scripts/build_rules.py` でルール表を作る（必要なら通帳キーワードを追加）
5. `scripts/journalize.py` で仕訳を作り、Excelを出す
6. 結果を報告する

作業用のファイルは一時フォルダに置き、最後にExcelだけをユーザーに渡す。

## 1. 資料の確認

次が揃っているか確認する。足りなければ、それだけを聞く（何度も質問しない）。

- **過去の総勘定元帳**：通帳と同じ銀行口座の部分。直近1年分あると精度が上がる。Excel・CSV・PDF・画像のどれでもよい。
- **通帳のコピー**：画像またはPDF。
- **預金の科目名と補助科目**（例：普通預金／〇〇銀行）：元帳から分かれば聞かない。

元帳に複数の口座が混ざっていたら、通帳と同じ口座の部分だけを使う。

## 2. 元帳を ledger.csv にする

UTF-8のCSVで、次の列にする（列名は完全に同じにする）。

| 列 | 内容 |
|---|---|
| 日付 | 2026-04-01 の形（和暦は西暦に直す） |
| 相手勘定科目 | 預金の相手側の科目 |
| 相手補助科目 | なければ空欄 |
| 税区分 | 元帳の表記のまま（例：課対仕入10%）。なければ空欄 |
| 摘要 | 元帳の表記のまま |
| 入金額 | 預金の借方の金額（入金） |
| 出金額 | 預金の貸方の金額（出金） |

- Excel・CSVは Python（openpyxl など）で読み、列を対応させる。会計ソフトごとに列名が違うので、中身を見て判断する。
- 「諸口」になっている複合仕訳は、相手科目ごとの行に分けられるなら分ける。分けられなければ「諸口」のまま残す。
- 前期繰越・月計・累計の行は入れない。
- 元帳の科目名・補助科目名・税区分は**一字一句そのまま**使う（会計ソフトに取り込むときにずれないように）。

## 3. 通帳を読み取って passbook.csv にする

UTF-8のCSVで、次の列にする。

| 列 | 内容 |
|---|---|
| 日付 | 2026-04-01 の形 |
| 摘要 | 通帳の表記のまま（半角カナもそのまま） |
| 出金額 | 支払った金額 |
| 入金額 | 預かった金額 |
| 残高 | 通帳の差引残高。印字がない行は空欄 |
| 読取メモ | 読みにくい箇所があれば書く。なければ空欄 |

読み取りのルール：
- 通帳に印字された順番どおりに、1行ずつ書く。合算や並べ替えをしない。
- 「繰越」「前ページより」などの行は、残高だけを入れて出金・入金を空欄にする（残高チェックの起点になる）。
- **読めない文字・数字を推測で埋めない。** 一番ありそうな値を入れたうえで、読取メモに「金額の3桁目が不鮮明」などと書く。
- 和暦（例：08-04-01、R8.4.1）は西暦に直す。年が書かれていなければ、元帳と前後の行から判断し、判断できなければユーザーに聞く。
- 何ページもある場合は、全ページを1つのCSVにまとめる。

## 4. ルール表を作る

```bash
python scripts/build_rules.py ledger.csv rules.json
```

ルール表には、過去の仕訳を「入出金・相手科目・補助科目・税区分」でまとめたパターンが入る。パターンごとに次の情報を持つ。
- 照合用のキー（摘要から相手先名を取り出したもの）
- 金額の範囲、毎回同額か、主な日付
- 振込手数料が同じ日に付く割合と、その金額（手数料を当方が負担しているか）
- 借入金なら、元本と利息の返済履歴

**通帳キーワードの追加（重要）**：元帳の摘要が漢字（例：丸々商事 支払）で、通帳がカナ（例：ﾌﾘｺﾐ ﾏﾙﾏﾙｼﾖｳｼﾞ(ｶ）のときは、そのままでは一致しない。
`rules.json` の各パターンの `examples` を見て、通帳での表記がはっきり分かるもの（会社名の読みなど）だけ `keywords.csv` に書き、作り直す。

```csv
相手勘定科目,相手補助科目,通帳キーワード
買掛金,丸々商事,ﾏﾙﾏﾙｼﾖｳｼﾞ
```

```bash
python scripts/build_rules.py ledger.csv rules.json --keywords keywords.csv
```

読みが確実でないものは書かない（間違ったキーワードは誤った「過去一致」を生む）。そういうものはJEVの判定に任せる。

## 5. 仕訳を作る

```bash
python scripts/journalize.py passbook.csv rules.json 仕訳_会社名_銀行名_期間.xlsx --bank-account 普通預金 --bank-sub 〇〇銀行
```

- `--bank-account` と `--bank-sub` には、元帳での預金の科目名と補助科目名を入れる。
- JEVのAPIキーは、環境変数 `TYPESAFE_API_KEY`、またはこのスキルのフォルダにある `jev_config.json` から読む。キーがなければ、JEVを使わずに処理し、その旨を表示する。
- ユーザーがチャットにAPIキーを書いた場合は、`TYPESAFE_API_KEY=... python scripts/journalize.py ...` のように、そのコマンドの実行時だけ使う。ファイルに保存しない。
- JEVに接続できない場合（ネットワークの制限など）も、自動でJEVなしに切り替わる。エラーの内容を報告に書く。
- 必要なライブラリは openpyxl だけ。なければ `pip install openpyxl` を実行する。

判定の仕組み：
1. 過去の摘要と一致し、科目が1つに決まるもの → **過去一致**（JEVには聞かないので速い）
2. それ以外は、似ている過去パターンを最大12個に絞り、JEVに「どれと同じ取引か、どれでもないか」を選ばせる
   - 確信度が80%以上 → **JEV判定**
   - 50〜80% → **要確認**（候補の科目を入れる）
   - それ未満、または「どれでもない」 → **不明**
3. 借入返済は、過去の返済履歴から元金均等か元利均等かを判定し、元本と利息に分ける → **推定**
4. 過去に「支払と同じ日に振込手数料」が付いていた相手先で、通帳に手数料の行がない場合は、引落額に手数料が含まれていると考えて分ける → **推定**
5. JEVを使えないときは、似ている候補があれば **要確認**、なければ **不明**

## 6. 報告

Excelファイルを渡し、チャットでは次だけを短く伝える。
- 判定ごとの件数（過去一致・JEV判定・推定・要確認・不明）
- **残高チェックの結果**：不一致があれば、その行と差額。まず通帳の読み取りを見直し、読み間違いが分かれば passbook.csv を直して作り直す。直せなければ、そのまま報告する。
- 「不明」と「要確認」の一覧（日付・摘要・金額・理由）
- JEVを使えたかどうか

やってはいけないこと：
- 「不明」の行に、Claudeの推測で科目を入れること。ユーザーに聞かれたら、チャットで「候補としては〇〇が考えられる。理由は〜」と答えるのはよいが、Excelの「不明」は書き換えない。
- 元帳にない科目名や補助科目名を作ること。
- 借入返済の推定額を、返済予定表で確かめた値のように書くこと。

## Excelの中身

| シート | 内容 |
|---|---|
| 仕訳 | 1行1仕訳。判定ごとに色分け（JEV判定＝緑、推定＝黄、要確認＝橙、不明＝赤）。根拠と残高チェックの列付き |
| 集計 | 件数、JEVの使用状況、残高の不一致、読み取りに自信がない箇所 |
| 通帳読取 | 通帳から読み取った内容と残高チェック。原本との照合用 |
| ルール表 | 元帳から作った仕訳パターン。科目の当てはめ方の確認用 |
